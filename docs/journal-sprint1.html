Architecture & Organisation Angular

Essentiel
Structure des dossiers
core / features / shared / models / services — séparer les responsabilités dès le départ
Essentiel
Convention de nommage
*.component.ts · *.service.ts · *.pipe.ts · *.model.ts · *.guard.ts
Essentiel
inject() vs constructeur
Angular 14+ préfère inject() — plus lisible, obligatoire en mid-level
Essentiel
provideHttpClient()
Obligatoire dans app.config.ts pour tous les appels HTTP — sans ça, rien ne fonctionne
Important
Standalone components
Plus de NgModule en Angular 17+ — chaque composant déclare ses propres imports
Important
Lazy loading des routes
loadComponent() — ne charge que ce qui est nécessaire — améliore les performances
🎨

CSS & Responsive

Essentiel
Police globale sur tout le site
* { font-family } dans styles.css + override Material avec .mat-toolbar, .mat-mdc-*
Essentiel
Responsive avec breakpoints
@media (max-width: 768px) — mobile first. Cards selon device = basique en mid-level
Essentiel
CSS Grid & Flexbox
grid-template-columns pour les layouts. flex pour aligner les éléments dans une ligne
Important
Override Angular Material (MDC)
.mdc-snackbar__surface — Material 20 utilise MDC, les classes ont changé vs les versions précédentes
Important
Préserver les fonts d'icônes
.material-icons et [class^="fa-"] doivent être séparés du sélecteur * global
Important
object-fit: cover
Images qui remplissent leur conteneur sans déformer — essentiel pour les cards produits
💡
Règle d'or : Le responsive se code en même temps que le composant — pas après. Revenir dessus coûte 3x plus de temps.

Angular — Patterns & Bonnes Pratiques

Essentiel
@for / @empty / @if
Nouvelle syntaxe Angular 17+ — remplace *ngFor et *ngIf. À maîtriser absolument
Essentiel
BehaviorSubject + Observable
Partager l'état entre composants (ex: panier). La base de la réactivité Angular
Essentiel
AsyncPipe dans les templates
Évite les memory leaks — pas besoin de unsubscribe() manuellement
Important
combineLatest
Combiner plusieurs observables — items$ + total$ + count$ en une seule souscription
Important
Service singleton
providedIn: 'root' — une seule instance partagée dans toute l'app
Utile
CUSTOM_ELEMENTS_SCHEMA
Nécessaire pour intégrer des web components tiers (ex: Swiper) dans Angular

Git & Workflow

Essentiel
Branches par feature
feat/nom-feature — une US = une branche. Convention : feat / fix / refactor / style / docs
Essentiel
ESLint avant chaque commit
ng lint — 0 erreur obligatoire avant merge. Analyse statique = qualité de code
Essentiel
Résolution de conflits en local
git merge origin/develop — toujours résoudre en local, pas via l'interface GitHub
Important
--force-with-lease
Plus sûr que --force — vérifie que personne d'autre n'a pushé entre temps
Important
Story points vs temps
Points = complexité, pas des heures. Vélocité = points livrés par sprint
Important
Toggl — tracking du temps
Mesurer le temps réel par US pour calibrer les estimations des sprints suivants
🔒

Sécurité & Bonnes Pratiques Back

Essentiel
Jamais de secrets sur GitHub
appsettings.Development.json dans .gitignore — les bots scannent GitHub en permanence
Essentiel
.gitignore pour .NET
bin/ · obj/ · .vs/ · *.user — ne jamais commiter les fichiers de build
Important
Architecture microservices
Séparer Auth / Products / Media / Customers — une BDD partagée pour commencer
Important
localStorage avec précaution
OK pour le panier temporaire — jamais pour des tokens JWT ou données sensibles

Leçons Apprises — Sprint 1

🧠 Mindset

YAGNI — ne pas sur-engineerer dès le départ
Fonctionnel d'abord, design ensuite
Le responsive se code en même temps
Multiplier les estimations × 1.5 en début de projet

⚡ Qualité

@import CSS toujours en haut du fichier
!important nécessaire pour override Material
console.log supprimés avant le merge
Toujours garder 30% de buffer dans un sprint

🚀 Git

Résoudre les conflits en local uniquement
Branche propre si historique trop divergent
Le debug et les conflits = toujours sous-estimés
Lier chaque commit à une issue (#XX)
